Jointbox — Complete Guide

ISP management: subscribers, RADIUS, billing, reseller hierarchy, network diagnostics and compliance.

NestJS backend (:3001) · Next.js frontend (:3000) · PostgreSQL 16 · FreeRADIUS 3.2 · MikroTik RouterOS

Installation

git clone <repo> && cd "Jointbox panel"

# Backend
cd backend
npm install
cp .env.example .env          # set DATABASE_URL and JWT_SECRET
npm run db:push               # tables + Prisma client
npm run start:dev

# Frontend
cd ../frontend
npm install
npm run dev
Two commands, two jobs npm run db:push chains: fix ownership → push schema → regenerate the client. Any schema change needs it. npx prisma generate alone needs no database connection — useful when the database is down and you only need the build to pass.

Setup order

Each step depends on the one before it.

  1. Administration → Organization — your ISP, then franchises and dealers below.
  2. Network → NAS / Routers — each MikroTik with IP, RADIUS secret, and API username and password.
  3. Network → IP Pools — names must match the router exactly (case-sensitive). The page verifies against the live router and warns on mismatch.
  4. Plans & Stock → Packages — speed, price, duration, optional data allowance and FUP speed.
  5. Plans & Stock → Areas — coverage areas.
  6. Subscribers → Add — the customer can dial in immediately.

Router prerequisites

/ip pool add name=pppoe-pool ranges=10.10.10.2-10.10.10.254
/ppp profile set [find name=default] local-address=10.10.10.1
/radius add service=ppp address=<panel-ip> secret=<secret>
/radius incoming set accept=yes port=3799
/ip service enable api
API access is not optional Without the API username and password the panel cannot read router logs, verify pools, or force a disconnect — three of its most useful abilities.

A customer says they are offline Most common task

Work down this list. Each step rules out a whole class of cause, and the panel does most of the diagnosis for you. You should never need to SSH into a router.

  1. Open the subscriber. The header shows Online or Offline with the last disconnect reason in plain language.
  2. Router Log tab → Refresh from router. The panel reads the MikroTik live and states what is wrong — a reconnect loop, a missing pool, rejected authentication — with the fix.
  3. RADIUS tab. Flags two specific faults: conflicting addressing (both a pool and a fixed IP being sent), and no address source at all.
  4. If several customers are affected, open Insights → Analytics. If one VLAN, area or router is mostly down, it is a network fault, not a customer fault.
  5. Still stuck? Force Sync on the RADIUS tab rewrites their credentials and profile from scratch.
If the log says the pool does not exist The fix is on the MikroTik, not in the panel. Pool names are case-sensitive and must already exist on the router. Check Network → IP Pools for the mismatch warning.

Renewing and reactivating

Subscribers → Activation / Renewal. Five modes, because a month is not always the answer.

ModeUse when
Full periodNormal monthly renewal
Set days"Give him 5 days" — priced pro-rata
Until a dateAligning customers to month end, regardless of 28/30/31 days
Use balanceSpend their wallet, grant the days it buys
On credit"I'll pay Friday" — activates now, records the debt
Before you take any money A live preview shows days, price and the resulting expiry date. Renewals extend from the existing expiry when it is still in the future, so paying early never costs the customer days. The daily rate divides by the package's own duration, not a flat 30 — a 7-day package at 200 is 28.57/day, not 6.67.
Credit is capped Two unsettled extensions per subscriber. One is a favour; a stack is an unmanaged debt. Overdue credits are flagged daily but service is not cut automatically — that is a commercial decision for you, not a background job.

What suspension actually does

Suspension deletes the RADIUS credentials and kicks the live session. Removing credentials alone only blocks the next login, which on PPPoE can mean days of free service. Renewal restores them — both the automatic and manual paths re-sync to RADIUS.

Exporting a specific group

Subscribers → Export. Built to answer a question, not dump the table. Filters combine, so you can be as precise as you need.

  1. Pick conditions — package, dealer, area, router, status, expiry window, online now, missing CNIC, date range, free-text search.
  2. Watch the live count. It tells you how many match before you download.
  3. Choose columns (30 available), then Excel or CSV.
Example All 50 Mb customers under one dealer: tick that package, tick that dealer. Nothing else needed.
Passwords Only the ISP owner can include the Password column. Every export is written to the audit log with who ran it and exactly which columns and filters were used.

Static public IPs

Two ways in: the Static public IP field on the subscriber's Edit form, or Network → Static IPs.

Setting an address stops the pool being requested and reconnects the customer so it applies immediately. The address is recorded with full assignment history and starts its own monthly billing cycle.

Leave auth method alone A static address works on any authentication method. You do not need to switch to STATIC.
Before reassigning Clearing the field releases the address and stops billing. Do not give it to another customer until you have confirmed the previous one is actually off it.

Data allowances and FUP

Passing the allowance throttles rather than disconnects — the customer stays connected and billable, which avoids turning a heavy user into a cancellation.

  • Set Data Quota (GB) plus FUP Download/Upload on the package.
  • Leave the FUP speeds blank and the quota is never enforced — the right default for unlimited plans.
  • Usage shows live on the subscriber header, measured over their own billing period, so a renewal resets it.
  • KYC & Data Usage → Data usage lists everyone at 70% or beyond.
Commercially Anyone sitting at 100% is an upgrade conversation, not a problem.

Architecture

Customer CPE │ PPPoE ▼ ONU ──── PON port / splitter ──── OLT ──── BRAS (MikroTik) │ RADIUS ▼ FreeRADIUS ── PostgreSQL ▲ Jointbox backend ▲ Jointbox frontend

Multi-tenancy is enforced server-side by a recursive subtree query. Every account sees only its own descendants; only SUPER_ADMIN is global. Applied in the service layer, not the interface, so it cannot be bypassed by calling the API directly.

Addressing rules

The rule that breaks networks RADIUS sends either Framed-Pool or Framed-IP-Address — never both. Sending both makes the router take the literal address, fail, and drop the session in a loop every few seconds. The subscriber's RADIUS tab flags this if it ever occurs.

A common myth is that 255.255.255.254 means "let the NAS choose". RFC 2865 describes it that way; MikroTik does not honour it — it assigns the literal address, finds it unusable, and terminates. Use Framed-Pool alone.

Transmission path Auto-detected

The panel learns your ONU → splitter → OLT → BRAS path from the circuit-id the OLT stamps into each session, then uses it to say where a fault is rather than just that one exists.

Read top-down — the widest failure wins, because a dead OLT also makes every splitter beneath it look dead, and dispatching to a house in that case wastes a day.

ObservedCauseAction
<20% of a BRAS onlineBRASCheck router and uplink. Do not dispatch.
<25% of an OLT onlineOLT or its uplinkCheck OLT power and uplink fibre
<34% of one splitterPON port / splitterOne truck roll fixes everyone
Only this customerCustomer endDrop cable, ONU power, fibre bend
Requirements and honest limits Auto-detection needs PPPoE Intermediate Agent enabled on the OLT so it sends a circuit-id. Without it the path must be entered manually, and the panel says so rather than guessing. Optical power (Rx/Tx dBm) is not in RADIUS — those fields stay null until something polls the OLT over SNMP. Null means "not measured", deliberately distinct from "bad signal".

Billing and the reseller chain

Each account has a wallet; activating a subscriber settles down the chain automatically.

The rule to remember A price row is what that account pays. Their margin is what their child pays minus what they pay. A child never sees upstream pricing — that is by design, not an oversight.
  • Reseller Pricing — assign a package downstream with its price.
  • Wallets are controlled by the parent. Children can be given permission to set their own sell prices, but never to control wallets.
  • Reports → Debt by age ranks unpaid invoices by amount, not age — the oldest debt is usually small; the largest is what hurts cash flow.

CNIC verification

A PTA licence requirement, and your defence against resale fraud.

  • Record the CNIC number alongside the images. Punctuation is ignored when matching, so 35201-1234567-1 and 3520112345671 are correctly seen as the same person.
  • Verification refuses to approve without a number, both image sides, and a non-expired CNIC.
  • Shared CNICs are listed but not blocked — families and businesses legitimately share one. The point is to make them deliberate rather than accidental.
  • Export the subscriber register as CSV when a regulator asks.

Analytics

Insights → Analytics leads with a plain sentence: everything normal, or which segments need attention. Below that, the same base cut by VLAN, area, dealer, router and package.

What makes it useful Every segment shows ONLINE against ACTIVE. The gap between them is where faults hide — a VLAN with 40 active customers and 3 online is broken, and a total on its own can never tell you that. Healthy segments are hidden by default so problems are what you see first.

Small segments are judged gently: two of three offline means nothing, while 33% of sixty is an outage. Flagging the former trains people to ignore the indicator.

Troubleshooting

Customer reconnects every few seconds

The router log will say could not determine remote address (the pool does not exist on the router) or show 255.255.255.254 being issued. Check Network → IP Pools for the mismatch warning.

Property 'x' does not exist on type 'PrismaService'

The Prisma client is stale. Run npx prisma generate. This is always the cause when you see a wall of these after a schema change.

Can't reach database server

PostgreSQL is down. Check df -h before restarting — a full disk from accumulated backups is a common cause, and restarting without freeing space just repeats the crash. FreeRADIUS uses the same database, so this takes authentication down too.

AddrParseError(Ip)

A non-IP value is being matched against an INET column. Usually a nasipaddress carrying a prefix such as 192.168.1.1/32.

Renewed customer still cannot connect

Their RADIUS credentials were deleted by suspension and not restored. Press Force Sync on the subscriber's RADIUS tab.

Router Log tab is empty

The NAS is missing its API username and password under Network → NAS / Routers.

Scale

Design targets: 200+ NAS and large subscriber counts.

  • Bounded worker pools — never all routers at once
  • Split poll cycles: fast 30 s for sessions, slow 5 min for health
  • Bulk UPDATE … FROM (VALUES …) instead of per-subscriber writes
  • Aggregate queries per page rather than per row
  • Router logs deduplicated by fingerprint and pruned at 14 days
The trap that produces impossible numbers Postgres BIGINT arrives in JavaScript as a string. Always Number() before arithmetic — otherwise + concatenates, and a usage figure becomes something like 7.7e+251 GB.
