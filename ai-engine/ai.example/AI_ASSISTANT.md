CRM assistant
=============

The floating CRM assistant button is available to signed-in staff. System guide works without an AI subscription: it retrieves built-in workflow guidance and a fresh, permission-scoped database summary. This mode is deterministic guidance, not a language model. It covers customer registration, documents, invoices, recharge, receipts, inventory, QR, tickets/TAT, recovery, staff, hierarchy, designations, expenses, roles, reporting and customer portal limitations. Update crm_assistant.GUIDE when workflows change.

To enable AI analysis, copy ai.example.json to ai.local.json. Set enabled to true, select an OpenAI Responses-compatible model available to your account, and set the API key locally. Alternatively, set OPENAI_API_KEY and CRM_AI_MODEL on the server, with enabled still set in ai.local.json. Never paste keys into chat or browser JavaScript. The local configuration file is excluded from version control. No paid AI requests occur while AI analysis is disabled. No third-party calls were made during automated tests.

AI analysis sends the question, built-in system guide, aggregate operational data and up to five explicitly matched customer identity/status records to the OpenAI Responses API. Customer contact details, documents, bank details, employee salaries, passwords, configuration and API keys are not included. Financial summaries and matched customer balances require Payments read permission. Technician tickets and stock issues retain assignment scoping. The API uses store:false; this does not assert zero provider retention. API usage is billed by the provider.

The assistant has no write tools, SQL generation/execution tools, file access or message sending tools. It cannot record payments, activate customers, change permissions or contact customers. Its visible conversation is temporary and cleared on logout; no conversation history is stored by this app. Each question uses fresh context independently, so include the subject in follow-up questions. There is a ten-request-per-user/15-minute limit. Customer questions can match exact name, username or 9-digit payment ID. Data not supplied in the summary is unavailable; broad ad-hoc historical queries are not supported.

Both localhost and demo use the same code. Configuration is server-local and currently shared between those two processes on this laptop. Use separate configurations/environment secrets on separate deployments. ChatGPT subscriptions do not supply this API configuration.

Implementation follows the official Responses API guidance: https://developers.openai.com/api/docs/guides/migrate-to-responses

Record lookups: the assistant can now list permitted customers, invoices, receipts, tickets, inventory, stock issues, recoveries, employees, packages and expenses. Ask for today/yesterday/this month/last month, last N days (up to 366), YYYY-MM or YYYY-MM-DD to YYYY-MM-DD. Invoice YYYY-MM means billing month; other date filters use the labeled date field. Results are limited to 20 rows but totals include all matching rows. Customer matches can use full name, a name token of at least four characters, username or payment ID; shared names can return multiple customers. Every answer is a fresh independent lookup. Salary, bank, identity and secret fields remain excluded. These deterministic lookups also work without an AI API key.

Urdu/Roman Urdu: built-in lookup vocabulary recognizes common phrases such as kitni sali hoi ha ajj (today sales), aaj kitni wasooli hui (today collections), kal (yesterday for retrospective lookups), is mahine (this month), baki/baqaya (customer balance), shikayat (tickets), kam stock, kharcha and their Urdu-script equivalents. This is bounded intent matching, not general translation. Sales uses the existing dashboard definition: MRC invoices raised plus paid OTC receipts; new customer joining counts and distinct recharge activation counts are shown separately. Free-form Urdu conversations still require connected AI mode.

Summary-only replies: assistant answers now show only a concise summary and key totals rather than individual record lists or full histories. This applies to built-in English, Urdu/Roman Urdu lookups and the connected AI instructions.

Graphical replies: short answers are accompanied by server-built aggregate KPI tiles and same-unit comparison bars when numeric results are available. Charts are built from authorized CRM data, not generated by the language model. Record rows are not returned in the graphical payload. Workflow explanations and permission errors have no chart.
